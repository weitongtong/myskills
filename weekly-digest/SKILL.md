# 周报逐字稿

## 动作路由

收到消息后，按以下规则判断并执行。

| 触发方式 | 动作 |
|---------|------|
| 发送内容（URL/文件/文本） | 智能判断是否收录，确认后执行**收录流程** |
| "先看看" + 内容 | 仅执行**预览流程**，不写入文档 |
| "本周分享稿" / "本周收录" | 执行**查询流程** |

**智能判断规则**：
- 消息包含 URL 或文件附件 -> 大概率是收录请求，直接执行收录流程
- 纯文本且内容较长（像文章摘要/要点） -> 直接执行收录流程
- 不确定（日常对话、简短问题等） -> 反问用户「这条内容要收录为分享稿吗？」

## 输出规范

执行收录/预览流程时，**严格遵守**以下输出规则：

- **中间步骤**（提取内容、生成逐字稿、写入文档）：每步仅输出一行简短状态提示，例如：
  - `正在获取文章内容…`
  - `正在生成逐字稿…`
  - `正在写入飞书文档…`
- **最终回复**（收录流程第五步 / 预览流程的预览回复）：这是**唯一**展示逐字稿全文的地方
- **禁止**在中间步骤输出逐字稿全文、大段原文摘要或重复的标题内容

## 首次配置

执行任何脚本前，先检查 `{baseDir}/.env` 是否存在。如果不存在，引导用户配置：

1. 提示用户提供飞书应用的 `app_id` 和 `app_secret`（可复用飞书通道已有的凭证）
2. 询问是否需要指定文档存放目录（`folder_token`，在飞书云盘文件夹 URL 中可找到）
3. 询问租户域名（如 `xxx.feishu.cn`，默认 `bytedance.feishu.cn`）
4. 将配置写入 `{baseDir}/.env`：

```
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
FEISHU_FOLDER_TOKEN=
FEISHU_DOMAIN=bytedance.feishu.cn
```

5. 运行 `node {baseDir}/scripts/doc-manager.mjs status` 验证连通性
6. 如果返回权限错误，提示用户去飞书开放平台后台为应用添加 `docx:document`（文档读写）和 `drive:drive`（云空间管理）权限，然后重新发布应用版本

## 收录流程

### 第一步：提取内容

根据输入类型提取原始内容：

- **URL**：**必须**使用以下脚本提取网页正文：

```bash
node {baseDir}/scripts/fetch-content.mjs "URL地址"
```

脚本输出 JSON，其中 `text` 字段为提取的正文，`title` 字段为网页标题。如果脚本返回错误，告知用户并建议直接粘贴文章内容。

**禁止事项**（URL 提取阶段）：
- **禁止**使用 `web_fetch` 工具（对微信公众号等网站不可用）
- **禁止**使用浏览器类工具（playwright、browser、chrome-devtools 等）
- **禁止**使用 `web_search` 搜索替代
- 只允许使用上面的 `fetch-content.mjs` 脚本

- **文件**：读取用户发送的文件内容（飞书通道会自动下载附件）
- **文本**：直接使用用户发送的文本

### 第二步：生成逐字稿

根据提取到的内容，生成一段**可以直接朗读的口语化分享稿**。

**生成要求**：

1. **开场引入**（1-2 句）：用自然的口吻说明为什么要分享这个内容，引起听众兴趣
2. **核心要点**：用通俗易懂的语言提炼文章的关键信息，避免照搬原文
3. **延伸思考**（1-2 句）：简短的个人观点或启发
4. **语言风格**：口语化、自然，像在跟朋友聊天一样；避免书面语和学术腔
5. **长度**：300-800 字
6. **过滤噪音**：自动忽略原文中的广告、招聘信息、公众号推广、扫码关注等无关内容

**逐字稿示例**（供参考风格，不要照搬）：

```
今天看到一个挺有意思的东西，Anthropic 发布了 Claude Managed Agents。简单来说，就是他们开始提供一整套现成的基础设施，让你可以快速搭建能长期干活的 AI Agent。

这件事为什么值得关注呢？以前我们想让 AI 持续帮我们干活，得自己搭服务器、处理崩溃恢复、管理权限，特别麻烦。现在 Anthropic 把这些全包了——你只需要告诉它干什么，剩下的环境、安全、监控它都帮你搞定。

最有意思的是他们的架构设计，把 AI 的"大脑"和"手脚"彻底分开了。执行环境崩了？换一个继续跑，大脑完全不受影响。这让 Agent 的稳定性提升了一大截。

定价也值得一提，每小时只要 0.08 美元。这意味着 AI 劳动力的成本已经低到了一个新的量级，企业批量部署 Agent 的门槛大幅降低了。
```

### 第三步：提取标题

从原始内容中提取一个简短的标题（不超过 30 字）。如果是 URL，优先使用网页标题；如果是纯文本，根据内容概括一个标题。

### 第四步：写入飞书文档

将逐字稿写入本周的飞书文档。先用 `write_file` 将 JSON 写入临时文件，再 pipe 给脚本：

```bash
write_file("{baseDir}/data/_pending.json", JSON.stringify({
  "title": "提取的标题",
  "source": "来源URL或文件名",
  "content": "生成的逐字稿全文"
}))
```

然后执行：

```bash
cat {baseDir}/data/_pending.json | node {baseDir}/scripts/doc-manager.mjs append
```

> 如果 `node` 命令不可用，尝试使用 `~/.deskclaw/node/bin/node` 完整路径。

脚本会自动判断是否需要新建本周文档，并输出 JSON 结果。

### 第五步：回复用户

根据脚本输出，用以下格式回复用户：

```
已收录 ✅

📄 {标题}

{逐字稿内容}

---
📎 已写入本周文档：{文档链接}
本周已收录 {N} 篇
```

## 预览流程

用户消息以"先看看"开头时，执行第一步到第三步（提取内容 + 生成逐字稿），但**不执行第四步**（不写入文档）。

直接将逐字稿回复给用户：

```
📄 {标题}（预览）

{逐字稿内容}

---
💡 如需收录，请回复「收录」
```

用户回复「收录」后，使用之前生成的逐字稿执行第四步和第五步。

## 查询流程

运行查询脚本并返回结果：

```bash
node {baseDir}/scripts/doc-manager.mjs status
```

将输出格式化后回复用户。

## 错误处理

### doc-manager.mjs 退出码

| 退出码 | 含义 | 处理方式 |
|--------|------|----------|
| 0 | 成功 | 正常处理脚本 JSON 输出 |
| 1 | 配置缺失（.env 不存在或缺少必要字段） | 引导用户执行首次配置 |
| 2 | API 错误（权限不足、网络错误等） | 展示错误信息，提示用户检查飞书应用权限 |
| 3 | 内容重复（已收录过相同来源） | 告知用户该内容已收录，询问是否要重复收录 |

### 脚本输出格式

脚本所有输出均为 JSON，包含 `status` 字段：

- `{"status":"ok", ...}` — 成功
- `{"status":"duplicate", "title":"...", "source":"..."}` — 内容重复
- `{"status":"error", "message":"...", "code":"..."}` — 错误
